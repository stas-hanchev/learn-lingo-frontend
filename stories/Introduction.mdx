# LearnLingo UI

This Storybook is the component catalogue of the LearnLingo frontend (Next.js App Router, TanStack Query,
zustand, Formik + Yup, CSS Modules). Every story is also an automated test: interactions, network
responses and accessibility are checked on each run.

## Getting started

```bash
npm run storybook        # dev server on http://localhost:6006
npm test                 # run every story as a test (Vitest browser mode + Playwright)
npm run test:watch       # the same in watch mode
npm run test:coverage    # with a coverage report in coverage/
npm run build-storybook  # static build in storybook-static/
```

Storybook and the tests need `NEXT_PUBLIC_PROXY_API_URL=/api` in `.env` (CI sets it in the workflow).
Every request to `/api` is answered by Mock Service Worker, so no backend is required.

Each component has an autogenerated **Docs** page. Prop descriptions come from JSDoc comments on the
component's props interface, so document props there rather than in `argTypes`.

## Writing a story

Stories live next to the component: `components/Foo/Foo.stories.tsx`.

```tsx
import type { Meta, StoryObj } from '@storybook/nextjs-vite'
import { expect, fn } from 'storybook/test'

import Foo from './Foo'

const meta = {
    title: 'Section/Foo',
    component: Foo,
    tags: ['autodocs'],
    args: { onChange: fn() },
} satisfies Meta<typeof Foo>

export default meta
type Story = StoryObj<typeof meta>

export const Default: Story = {
    play: async ({ canvas, userEvent, args }) => {
        await userEvent.click(canvas.getByRole('button', { name: 'Apply' }))
        await expect(args.onChange).toHaveBeenCalled()
    },
}
```

Conventions:

- `title` is `Section/ComponentName`, using one of the sections above.
- Story names describe a state or a scenario in PascalCase: `Guest`, `ServerError`, `InvalidEmail`.
- Query elements by role and accessible name (`getByRole('button', { name: 'Log in' })`). If that is
  impossible, the component probably has an accessibility gap — fix the component.
- Callbacks are `fn()` spies, so calls appear in the Actions panel and can be asserted.
- Modals and toasts render into `document.body`; query them with `screen`, not `canvas`.

## Global setup

These are configured in `.storybook/preview.tsx` and apply to every story:

| What | How to use it |
| --- | --- |
| Auth state | `parameters: { auth: 'authenticated' }` logs in a mock user (`mocks/teachers.ts`); the default is a guest |
| Favorites | `parameters: { favorites: [janeSmith] }` seeds the mocked favorites list |
| TanStack Query | Every story gets a fresh `QueryClient` without retries |
| Toasts | The toaster is always rendered; toasts are cleared between stories |
| Accessibility | axe runs after every story; any violation fails the test |

### Mocking the API

Default handlers in `mocks/handlers.ts` emulate the backend (`/api/teachers`, `/api/favorites`,
`/api/auth/*`) on top of the fixtures in `mocks/teachers.ts`. Override one endpoint per story:

```tsx
import { delay, http } from 'msw'
import { errorResponse } from '@/mocks/handlers'

export const ServerError: Story = {
    beforeEach: ({ msw }) => {
        msw.use(http.post('/api/favorites/:id', () => errorResponse(500, 'Internal server error')))
    },
}

export const Loading: Story = {
    beforeEach: ({ msw }) => {
        msw.use(http.get('/api/teachers', () => delay('infinite')))
    },
}
```

A request to `/api/*` without a handler is reported as an error, so it never silently reaches the
network.

## Known limitations

- `nextjs.appDirectory: true` crashes with Next 16.4 in Storybook 10.6. Client components do not use
  `next/navigation` yet; if one starts to, this has to be revisited.
- `next/link` is mocked: clicks are logged as `next/link::Link` in Actions and never navigate.
- Async server components (`app/favorites/page.tsx`) have no stories; their content is covered by
  `TeacherList`.

## Reviewing changes

Every pull request runs `npm test` and builds Storybook in CI. To discuss a component, link to its
story (for example `?path=/story/teachers-favoritebutton--server-error`) instead of attaching
screenshots.
